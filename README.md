# Kamali

Интернет-магазин на Laravel 12, Vue 3, Inertia 2 и Filament 4. Исходная верстка сохранена в корневых HTML-файлах; её ресурсы перенесены в `public/assets`. Рабочий сайт обслуживается **только из `public/`**.

## Windows + Docker + WSL2

Для локальной разработки на вашем компьютере используйте [пошаговую инструкцию Docker/WSL2](docs/docker-wsl.md). Все зависимости устанавливаются внутри контейнеров:

```bash
# В Linux-консоли, из папки ~/projects/kamali
bash scripts/docker.sh setup
bash scripts/docker.sh admin admin@example.com
```

Сайт после запуска доступен на вашем компьютере по адресу `http://localhost:8080`. Для следующих запусков — `bash scripts/docker.sh up`, для Vue с быстрым обновлением — `bash scripts/docker.sh dev`. Секреты автоматически создаются в `.env.docker`; исходный `.env` не перезаписывается.

## Запуск без Docker

Нужны PHP **8.4.27+** (версия закреплена для разрешения зависимостей), Composer **2.9.5+**, Node.js 22.12+ и расширения PHP: curl, dom, fileinfo, intl, mbstring, openssl, PDO/pgsql, tokenizer, xml, xmlreader, xmlwriter, zip. Рабочая и тестовая базы — PostgreSQL; проверено на PostgreSQL 17.11. Расширение `pdo_pgsql` обязательно и проверяется Composer.

Перед установкой подготовьте базы `kamali` и `kamali_test` с владельцем `kamali`. Например, на Linux с установленным PostgreSQL:

```bash
sudo -u postgres createuser --pwprompt kamali
sudo -u postgres createdb --owner=kamali kamali
sudo -u postgres createdb --owner=kamali kamali_test
cp .env.example .env
```

Укажите в `.env` свои `DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME` и `DB_PASSWORD`. Пароль в пример конфигурации не включён. Затем:

```bash
./scripts/setup.sh
./scripts/dev.sh
```

Скрипт устанавливает зависимости по lock-файлам, создаёт `.env` только при его отсутствии, запускает миграции и добавляет начальные страницы и контент. Повторный запуск не перезаписывает редакторские изменения и ключ приложения. По умолчанию используется PostgreSQL; сервер и база должны существовать до запуска скрипта. SQLite-файл больше не создаётся.

### PostgreSQL в подготовленной облачной среде

PHP с `pdo_pgsql` и PostgreSQL 17 установлены в `/workspace/.toolchain`. Перед запуском приложения после восстановления среды выполните:

```bash
./scripts/postgres-local.sh start
./scripts/dev.sh
```

Локальный PostgreSQL использует приватный Unix-сокет `/workspace/.toolchain/postgres-local/run`, порт сокета `55432` и peer-аутентификацию текущего пользователя Linux. TCP-подключения к этому кластеру отключены, пароль ему не нужен. Подключение уже настроено в локальном `.env`; эти параметры не заменяют настройки вашего рабочего сервера. Команда `start` повторяема и создаёт только отсутствующие базы `kamali` и `kamali_test`, сохраняя существующие данные. Для остановки: `./scripts/postgres-local.sh stop`.

Для удалённого сервера с проверкой TLS задайте `DB_SSLMODE=verify-full` и при необходимости `DB_SSLROOTCERT=/path/to/ca.crt`. Сведения о подключении, миграциях и тестах — [docs/postgresql.md](docs/postgresql.md).

Для разработки Vue с горячим обновлением запустите `npm run dev` во втором терминале. Для работы без Vite-сервера достаточно `npm run build` и PHP-сервера.

### Администратор

```bash
php artisan shop:admin admin@example.com
```

Команда запросит имя и скрытый пароль; стандартных административных аккаунтов и паролей нет. Уже существующий покупатель автоматически администратором не становится. Панель: `/admin`. В облаке перед PHP-командами: `export PATH=/workspace/.toolchain/bin:$PATH`.

### Демокаталог

Обычная установка не создаёт вымышленные товары. Для локальной проверки можно отдельно выполнить:

```bash
php artisan db:seed --class=DemoCatalogSeeder
```

Это три демонстрационных товара из верстки. Они не предназначены для публикации магазина. В текущей рабочей среде демокаталог установлен для проверки сценариев.

## Что работает

- Маркетинговые страницы перенесены в Vue с исходными классами и стилями. Шапка, подвал, корзина и поиск — общие компоненты. Шрифты и UI-библиотеки поставляются локально.
- Каталог: категории, поиск, сортировка, пагинация, варианты товара, цены и остатки из базы; избранное покупателя.
- Сессионная корзина доступна гостям; оформление требует входа. Почта с паролем, регистрация, восстановление пароля, профиль и история заказов.
- Создание заказа проверяет цены и остатки, сохраняет снимок позиций и уменьшает доступный остаток в транзакции. Повторная отправка той же формы не создаёт второй заказ.
- Filament: отдельные страницы создания и редактирования товара; простые и вариативные товары, атрибуты и генерация комбинаций, несколько категорий и подборок через чекбоксы, SKU и артикул, загрузка изображений и галерея с сортировкой, статусы и публикация по расписанию. Также заказы, покупатели, страницы/SEO, тексты/ссылки/изображения и медиатека. Инструкция — [docs/product-editor.md](docs/product-editor.md).

## Управление контентом

В разделе «Тексты, ссылки и изображения» найдите блок по исходному тексту или отфильтруйте по странице. `shared` — общие элементы, фоновые изображения и подписи интерфейса. Для изображений сначала загрузите файл в медиатеку, затем выберите его в соответствующем блоке или товаре.

В «Страницы и SEO» редактируются заголовок, SEO-описание, адрес и публикация. Поле переопределений позволяет назначить странице собственные значения ключей блоков — например, создать ещё одну статью на шаблоне `article`, не меняя существующую. Ссылку на неё можно назначить карточке блога. Количество и расположение блоков задаются Vue-шаблоном; свободного конструктора дизайна нет. Подписи системных ошибок и расчётные значения не являются редакторским контентом.

Начальный контент взят из предоставленной верстки, включая юридические тексты, рекламные обещания и примеры отзывов. Перед публикацией замените их на утверждённые данные. Исходные HTML-файлы служат эталоном и не изменяются при редактировании через админку.

## Внешние сервисы и границы первой версии

- **1С:** предусмотрен транзакционный импорт нормализованного JSON **по SKU** товара и вариаций; артикул хранится отдельно. Это ещё не готовый CommerceML-обмен: потребуется адаптер под выбранную конфигурацию и согласование источника цен/остатков и выгрузки заказов. Формат — [docs/integrations.md](docs/integrations.md).
- **Оплата:** банк не выбран. Платёжные ссылки и обработчики уведомлений не подключены. Заказ создаётся с `payment_status=not_started`; кнопка не имитирует списание денег.
- **Доставка:** СДЭК и свой курьер сохраняются как выбранный способ. API СДЭК, карта ПВЗ, тарифы и создание накладной пока не подключены. Стоимость доставки неизвестна (`NULL`), её согласует менеджер. Сумма товаров не выдаётся за окончательную сумму с доставкой.
- **SMS:** провайдер не выбран, поэтому вход по телефону не показывается. Работает вход по почте.
- **Почта:** для разработки `MAIL_MAILER=log`; письма восстановления записываются в локальный журнал. Для реальной отправки настройте SMTP в `.env`/защищённых настройках окружения. Не добавляйте секреты в Git.
- Бонусы, промокоды, покупка сертификатов и автоматические возвраты отложены. Подарочная страница сохраняет первый экран формы и сообщает, что покупка пока недоступна. Служебные HTML-макеты состояний не публикуются как реальные кабинеты/заказы.
- Оформление и кабинет используют блоки исходного дизайна, но отсутствующие сервисы и вымышленные данные не воспроизводятся как рабочие функции. Финальную сверку всех интерактивных состояний нужно выполнить после подключения интеграций и наполнения.

Отмена заказа с возвратом остатка пока не предусмотрена: админка не предлагает фиктивное действие отмены. Для производства потребуется согласовать резервирование, оплату и отмену с 1С. Не используйте эту версию для приёма реальных оплат.

## Проверки

Тесты используют отдельную PostgreSQL-базу `kamali_test` с теми же параметрами подключения, что и приложение. Её нужно создать заранее. Конфигурация тестов отказывается работать с базой без `test` в имени; при запуске не задавайте `DB_DATABASE=kamali` в окружении тестового процесса.

```bash
php artisan test
npm run build
npm run test:browser
```

Среди серверных тестов есть проверки двумя независимыми PostgreSQL-подключениями: продажа последнего экземпляра и одновременная повторная отправка заказа.

Браузерный smoke-тест требует запущенный сайт на PostgreSQL, демокаталог и Chromium (`CHROMIUM_PATH`, по умолчанию `/usr/bin/chromium`). Он создаёт отдельного тестового покупателя и заказ, поэтому запускайте его только в локальной/тестовой базе.

Для сравнения маркетинговых страниц с исходником:

```bash
python scripts/serve-reference.py  # отдельный терминал, порт 8001
npm run test:visual
```

Скриншоты и геометрия сохраняются в `/tmp/kamali-visual`. Эталонный сервер предназначен только для локальной проверки. Скрипты импорта верстки использовались для первоначального переноса; не запускайте `import-layout.py` поверх доработанных компонентов.

Для развёртывания настройте рабочую БД, SMTP, HTTPS, `APP_URL`, `APP_ENV=production`, `APP_DEBUG=false`, защищённые cookies, резервное копирование и веб-корень `public/`. Внешние интеграции требуют отдельной настройки; эта версия не объявляется готовой к коммерческому запуску.
