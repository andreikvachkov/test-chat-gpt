# PostgreSQL

Приложение и feature-тесты настроены на PostgreSQL. Миграции, сидеры, админка, JSON-поля контента, корзина и оформление проверяются на настоящем сервере PostgreSQL 17, включая независимые одновременные подключения. SQLite не используется в штатной установке и тестовом наборе.

## Подключение

В `.env.example` заданы:

```dotenv
DB_CONNECTION=pgsql
DB_HOST=127.0.0.1
DB_PORT=5432
DB_DATABASE=kamali
DB_USERNAME=kamali
DB_PASSWORD=
DB_SSLMODE=prefer
```

Введите пароль своего пользователя локально в `.env` или через защищённые настройки сервера. `.env` и файлы `.env.*` с реальными параметрами исключены из Git и архива. Для remote TLS с проверкой имени сервера и цепочки сертификатов используйте `DB_SSLMODE=verify-full`, доверенный CA через `DB_SSLROOTCERT` и имя хоста из сертификата.

После изменения подключения:

```bash
php artisan config:clear
php artisan migrate --seed --force
```

`migrate` применяет новые миграции и не пересоздаёт существующие таблицы. Сидер сохраняет отредактированные блоки. Переход `DB_CONNECTION` на другой сервер не переносит данные автоматически: если в старой базе появятся реальные данные, понадобится отдельный перенос. Предыдущий локальный SQLite-файл в облачной среде сохранён; в новую PostgreSQL установлены начальный контент и демонстрационные товары.

Для production используйте отдельного пользователя приложения и резервное копирование PostgreSQL. Команды `migrate:fresh` и тестовый набор предназначены только для отдельной тестовой базы.

## Числа, поиск и транзакции

- Денежные суммы хранятся целыми копейками в `bigint`; остатки и количества — целыми числами.
- В PostgreSQL нет `UNSIGNED`: миграция `000004` добавляет ограничения `CHECK` на неотрицательные цены, остатки и суммы и положительное количество в строке заказа.
- Поиск использует `whereLike` Laravel, который на PostgreSQL генерирует `ILIKE`. Регистр русских и латинских букв не влияет на результат. Для русскоязычного каталога используйте UTF-8 и Unicode-совместимую локаль; в облачной среде используется `C.UTF-8`.
- Оформление выполняется в транзакции. Блокировки `FOR UPDATE` сериализуют операции по покупателю и вариантам товара. Уникальный ключ по покупателю и токену оформления дополнительно защищает от дублей.

## Тестовая база

Создайте отдельную БД `kamali_test` с правами на создание и удаление её таблиц. `phpunit.xml` выбирает `pgsql` и `kamali_test`; хост, порт и пользователь наследуются из параметров подключения среды. `DB_URL` для тестов принудительно очищается, чтобы URL основной базы не переопределил тестовое подключение.

```bash
php artisan test
```

`Tests\TestCase` перед миграциями требует PostgreSQL и наличие отдельного компонента `test` в имени базы. `PostgresConcurrencyTest` запускает два дочерних PHP-процесса с независимыми подключениями, синхронизирует начало операций и проверяет остаток и число заказов. GitHub Actions запускает PostgreSQL 17 и создаёт отдельные базы для feature-тестов и браузерного сценария.

## Локальный кластер облачной среды

`./scripts/postgres-local.sh start` использует подготовленные бинарники PostgreSQL в `/workspace/.toolchain/postgres`. Данные находятся в `/workspace/.toolchain/postgres-local/data`, сокет — в соседнем каталоге `run`, доступном только владельцу. Кластер запускается с `listen_addresses=''` и peer-аутентификацией локального пользователя.

Скрипт не устанавливает PostgreSQL и не управляет внешним сервером. Данные, бинарники и реальные параметры доступа не включаются в архив исходников. Восстановление облачного снимка сохраняет файлы, но требует повторного запуска процесса PostgreSQL; инструкции запуска сохранены в настройках среды.
