# Редактор товаров

В админке откройте **Каталог → Товары → Все товары → Создать**. Создание и редактирование открываются отдельными страницами (`/admin/products/create`, `/admin/products/{id}/edit`).

## Основные поля

- Название, адрес товара, полное описание с форматированием, краткое описание для карточки и первого экрана товара.
- **SKU** — уникальный ключ обмена с 1С. **Артикул** — отдельное поле, которое показывается покупателю. SKU простого товара совпадает с его единственной складской позицией; у вариативного товара родительский SKU и SKU каждой вариации различаются.
- В боковых блоках можно отметить несколько категорий и подборок. Категории идут деревом: дочерние расположены сразу под родительскими с отступом. Такой же порядок используется в списке категорий и выборе родителя; назначить категорию родителем самой себе или её потомку нельзя. Они создаются в разделах «Категории» и «Подборки». Старые текстовые метки при обновлении переносятся в подборки.
- В «Изображение товара» загрузите основную фотографию или выберите её в медиатеке с миниатюрами. В галерею можно загрузить несколько файлов, выбрать существующие и перетащить для изменения порядка. Основная фотография показывается первой. Загрузка добавляет файл в общую медиатеку. Удаление из галереи не уничтожает файл, который может использоваться в другом месте.
- Поля ID в 1С, «Состав», «Применение» и произвольная «Метка» из редактора убраны.

## Простой товар

Новый товар по умолчанию простой; пустого варианта в выборе типа нет. Блок «Данные товара» имеет вертикальные вкладки:

- **Основные:** обычная цена, цена распродажи, даты её начала и окончания, налоговый статус и класс.
- **Запасы:** SKU, отдельный артикул, GTIN/UPC/EAN/ISBN, MPN, управление остатком, количество, предзаказы, порог малого запаса, статус наличия и продажа по одной штуке в заказе. Для косметики сохранена подпись объёма, например `250 мл`.
- **Доставка:** вес в килограммах, длина/ширина/высота в сантиметрах и класс доставки. Новый класс можно добавить непосредственно при выборе.
- **Атрибуты:** значения характеристик, видимость на странице товара и использование для вариаций.
- **Вариации:** показывается у вариативного товара; отдельные SKU, артикул, идентификаторы, обычная и акционная цены, даты распродажи, остатки, предзаказ, вес/габариты, класс доставки, налоговый класс, фотография и описание каждой комбинации.
- **Дополнительно:** примечание к покупке, порядок вывода и включение отзывов.

Вкладки сопутствующих товаров, виртуальных и скачиваемых товаров нет. Цены вводятся в рублях, например `620,50`.

Распродажа действует только в заданном диапазоне дат; корзина и заказ используют актуальную цену. Если управление остатком выключено, доступность определяется статусом наличия. Предзаказы позволяют отрицательный остаток; вариант с уведомлением показывает клиенту «Под заказ». Общий остаток вариативного товара проверяется суммарно по всем его вариациям в заказе. «Продавать индивидуально» ограничивает весь товар одной штукой, даже при выборе разных вариаций. Примечание к покупке сохраняется в заказе и показывается покупателю после оформления.

Налоговый статус/класс и параметры доставки сохраняются как данные товара. Ставки налогов, расчёт тарифов СДЭК и уведомления о малом запасе требуют отдельной настройки магазина и интеграций; ввод полей не подключает эти сервисы.

## Вариативный товар

1. В разделе «Атрибуты» создайте атрибуты и значения: например, «Объём» → `100 мл`, `250 мл`; «Аромат» → `Sultan`, `Vanilla`.
2. В товаре выберите тип «Вариативный товар».
3. На вкладке «Атрибуты» добавьте нужные атрибуты, отметьте значения чекбоксами и включите «Использовать для вариаций».
4. На вкладке «Вариации» нажмите «Сформировать вариации из атрибутов». Будут созданы все комбинации (в примере четыре), максимум 100 на товар.
5. Для каждой комбинации укажите SKU, цену, остаток и при необходимости отдельный артикул. Ненужные комбинации можно выключить или убрать.

Повторная генерация сохраняет ID, SKU, цену и остаток существующей комбинации. Убранные вариации исключаются из продажи, но их записи сохраняются для истории заказов. При повторном добавлении той же комбинации восстанавливается её складская запись. Используемые атрибуты и значения нельзя удалить, пока они назначены товарам.

В каталоге кнопка вариативного товара открывает его страницу. Покупатель выбирает значения атрибутов и добавляет конкретную комбинацию со своей ценой и остатком. Оформление витрины использует исходные классы и стили.

## Медиатека

В разделе «Медиафайлы» показывается сетка превью с поиском и фильтром типов. Клик по файлу открывает большое превью, название, альтернативный текст, подпись, описание, размер, разрешение и URL. «Добавить медиафайлы» принимает несколько файлов за раз; лимит одного файла — 10 МБ.

Существующие изображения и видео из исходной верстки индексируются без копирования файлов. Фотографии, загруженные при редактировании товара, тоже попадают в общую сетку. Используемые сайтом файлы и ресурсы исходной верстки защищены от удаления; метаданные редактируются по правам роли. Выбор фото и галереи товара показывает только изображения.

## Публикация

Статусы: черновик, на утверждении, личный, опубликован, запланирован. Корзина удалённых товаров доступна через фильтр списка; товар можно восстановить. Личные, удалённые, неопубликованные и будущие товары недоступны в каталоге, поиске, избранном и оформлении заказа.

Дата в редакторе задаётся по **московскому времени**, в базе хранится UTC. Будущая дата при публикации автоматически переводит товар в запланированные. Docker запускает сервис `scheduler`, который каждую минуту переводит наступившие публикации в опубликованные. Проверка даты действует и на витрине, поэтому будущий товар не появляется раньше срока.

При запуске без Docker настройте `php artisan schedule:run` каждую минуту или запустите `php artisan schedule:work`. Ручная проверка: `php artisan shop:publish-scheduled`.

## Обновление существующего магазина

После распаковки новой версии поверх прежней папки выполните:

```bash
bash scripts/docker.sh setup
```

Команда применит миграцию и запустит планировщик. Миграция сохраняет товары, файлы, цены, остатки и связи с заказами; категории становятся множественными, метки превращаются в подборки. Для старых вариаций создаётся атрибут «Вариант». Старые SKU становятся ключами простых товаров, а для родителей с несколькими вариациями назначается `PRODUCT-{id}` — при необходимости измените его на ваш SKU. Существующие `.env.docker` и база не пересоздаются.
