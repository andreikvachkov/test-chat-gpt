# Границы интеграций

## 1С

`CatalogImporter` принимает массив нормализованных товаров. CLI: `php artisan shop:import-catalog /path/catalog.json`.

```json
[
  {
    "sku": "KAM-001",
    "article": "ART-001",
    "type": "simple",
    "name": "Мист Sultan",
    "slug": "sultan",
    "description": "Описание",
    "variants": [
      {
        "sku": "KAM-001",
        "name": "250 мл",
        "price_minor": 62000,
        "stock": 20
      }
    ]
  }
]
```

Ключ синхронизации — **SKU**, без ID в 1С. SKU товара и каждой вариации уникальны без учёта регистра. У простого товара одна складская позиция с тем же SKU. Артикул — отдельное поле для покупателя, он не служит ключом обмена.

Деньги в обмене — целые копейки; в админке цена вводится в рублях. `stock` — доступное для продажи количество, уже учитывающее резервы источника. Повторный пакет обновляет цены и остатки по SKU, сохраняя ID складских позиций, описания, изображения, категории, подборки и публикацию. Коллизии SKU и адресов откатывают пакет целиком. Новые товары создаются черновиками. Импорт не восстанавливает удалённые товары, не меняет тип существующего товара и не удаляет отсутствующие позиции.

У вариативного товара `type=variable`, отдельный родительский SKU и массив вариаций с собственными SKU. Существующие вариации обновляются по SKU, пропущенные остаются. Новые комбинации существующего товара сначала сформируйте в редакторе из атрибутов. Для нового вариативного товара в пакете у каждой вариации задаётся `attributes`, например `{"volume":"250-ml","scent":"sultan"}`: это коды атрибутов и их значений из админки. Неизвестные значения отклоняются, импорт не подменяет редакторские атрибуты произвольным текстом.

До подключения живого обмена нужно согласовать: конфигурацию/версию 1С, CommerceML или иной протокол, категории, единицы измерения и варианты, вид цен, доступные остатки, передачу локальных заказов и резервов, дедупликацию/порядок пакетов и частичных обновлений. Старый снимок склада нельзя безусловно применять после локальных продаж: адаптер должен учитывать неподтверждённые в 1С резервы. Текущий CLI — проверяемая граница адаптера, а не работающая синхронизация с 1С.

Открытого HTTP-загрузчика нет: способ аутентификации и доступ для 1С будут определены вместе с протоколом.

## Платежи, доставка, SMS

Контракты находятся в `app/Contracts`. Пока провайдеры не выбраны, контейнер возвращает реализацию `UnavailableIntegrations`, которая явно отказывает в выполнении операции. Она не выдаёт фиктивные ссылки, тарифы или успешную отправку SMS.

Для банка нужны создание платежа на согласованную сумму, проверка подписи уведомлений, сверка валюты/суммы/заказа, идемпотентная обработка повторов и чеки/возвраты по согласованным требованиям. Статус оплаты не редактируется вручную в админке.

Для СДЭК нужны реальные тарифы, пункты выдачи, ограничения грузов, накладные и отслеживание. Свой курьер пока предполагает ручное согласование. Пока стоимость неизвестна, `shipping_minor=NULL`, а `delivery_status=quote_required`.

SMS-вход требует ограничения частоты запросов и попыток, срока действия/одноразовости кодов и безопасного связывания телефона с существующим аккаунтом. Сам контракт отправки не реализует эти правила; маршруты SMS-входа сейчас отсутствуют.
